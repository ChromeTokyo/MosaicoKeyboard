# 方案 G：改造模块作为「常驻转接件」

- 日期：2026-09-20；提出：用户，整理：Claude（主控），实际模型 `claude-opus-5`。
- 定位：**产品与结构方向的候选提案，不是硬件技术结论，也不是已选定方案。** 连接器选型、寿命、力学与电流由 Chrome 判定，Hiro 复核。本文不含任何工程尺寸或额定值。
- **（2026-09-21 按 Hiro H0 F04 整改）** 本文原把「低插拔次数」写成「寿命／机械问题已解决」，并宣称本方案「唯一不依赖 E-01」。这些结论**已降为 ASSUMPTION 与结构候选**，原文保留在 Git 历史中。**H0 总结论仍为 CHANGES_REQUIRED**，本次整改由主控自查提交，是否关闭由 Hiro 判定，**不得据本文宣称已通过独立复核**。

## 1. 起因：两个未解问题

- **耐久**：模块槽连接器（V1.0 原理图标注 `B-2200R20P-B120`，形似 2.54 mm 排针排母）是为「偶尔更换模块」设计的，插拔寿命通常在几十至几百次量级。底座是每天插拔的用途，年均上千次。**这是用途与设计寿命的错配，不是把结构做结实能解决的。**
- **USB-C 被埋**：方案 E 旋转 90° 后，USB-C 落到贴着按键区的那一对面上，无法暴露（见 `review/claude/option-e-rotated-slot.md` 及其缺陷补记）。

## 2. 方案

```
Mosaico ──[模块槽连接器，装配时插一次，目标为此后不拔]── 改造模块 ──[适合频繁对接的接口]── 底座
```

- **模块槽这一端**：改造后的模块常驻插在 Mosaico 上，**目标插拔次数≈1**。
  **（2026-09-21 按 Hiro H0 F04 整改）** 原写「插拔次数≈1，**寿命问题消除**」已撤回，更正为 **ASSUMPTION**：降低插拔次数是设计意图，**不等于寿命与机械问题已消除**。即使长期不拔，连接器仍须承受**装配过程的插拔与对位、运输与使用中的振动、以及来自底座对接方向的侧向载荷与力矩**；这些载荷的量级与连接器的承受能力均未评估。
- **模块与底座这一端**：由模块另一面引出适合频繁对接的接口（弹簧针、磁吸或其他，选型属 Chrome）。
  **（2026-09-21 按 Hiro H0 F04 整改）** 原写「此类连接器的额定插拔寿命普遍高于机械排针若干个数量级」已撤回：**未选定具体器件即不能保证任何寿命等级**，该句是无据的量级承诺。正确表述为：这一类接口**通常以高对接次数为设计目标**，具体额定须在选型后由数据手册与验证确认。
- **Mosaico ＋ 模块作为一个整体**从上方落入底座。
- **USB-C 位于与模块槽垂直的另一对面上，意在保持暴露**——方案 E 的 USB-C 死结有望一并解除。**（2026-09-21 按 Hiro H0 F04 整改）** 原写「保持暴露——死结一并解除」已降为意图：**原生 USB-C 保持可达仍需结构证据**（常驻模块的厚度、底座仓壁与线缆插头的避让空间），未画结构前不能宣布解除。

## 3. 对 E-01 的敏感度（ASSUMPTION，待结构设计验证）

`E-01`（V1.2 的模块连接究竟是轴向对插的排针排母，还是磁吸侧向触点）是当前最关键的未知。**（2026-09-21 按 Hiro H0 F04 整改）** 本节原标题为「关键性质：对 E-01 不敏感」，并断言本方案是「目前唯一一个不依赖 E-01 结论的方案」。**该断言已撤回**：G 降低的是**插拔次数**，**对 E-01 的几何仍然敏感**——连接器的形态决定插接方向与顺序、固定与承力方式、整体外形厚度，以及 USB-C 的避让空间。

| E-01 的答案 | 对方案 G 的影响（均为 ASSUMPTION，待结构设计验证） |
| --- | --- |
| 轴向排针排母 | 常驻插入可把插拔次数降到≈1，**但保持力、抗侧向载荷与抗振动仍须验证**；轴向插接方向会约束模块与底座的相对布局 |
| 磁吸侧向触点 | 常驻吸附亦可降低插拔次数。**（2026-09-21 按 Hiro H0 F04 整改）** 原写「寿命更优；对位由磁吸自完成」已撤回：**磁吸的保持力与自对位能力取决于具体件的磁路、接触件形式与配合公差，未选件即不能假定**；侧向触点对相对滑移与污染也可能更敏感 |

**结论收窄**：G **可能**比 E／F 对 E-01 的某一答案更耐受，但**不是不依赖 E-01**，也**不是唯一可行的落地方式**。E-01 的答案仍须实物确认后再裁决。

**「插一次再不拔」尚不是已确认的使用方式。**（2026-09-21 按 Hiro H0 F04 整改）它与以下需求存在**尚未协调的冲突**：① 用户可能需要在同一槽位换插官方摄像头模块（对应用户决策 UD-A：接受分时使用则左槽合理，要求同时使用则应另评架构）；② 维修、返修与模块更换都需要能够拆下。该使用方式须由用户确认后才能作为结构设计前提。

## 4. 魔改的三级路径

### 第一级：到货当天，零固件改动

官方交互模块（实物丝印 `ESP-Mosaico Module-Interaction V0.2`）的两片输入区为**电容触摸焊盘**。BSP 的触摸模式头文件写明该输入同时检测「手指**以及机械按键对地短路**」。

因此：**从两片焊盘各引一根线到外接轻触开关，另一端接 GND。** 官方驱动原样识别为触摸事件，**固件无需任何改动**，即可验证「物理按键 → 模块 → BSP → 应用」整条链路。

价值：这条链路的验证**完全不依赖底座 PCB、不依赖机械设计、不依赖任何冻结尺寸**，是目前可最早取得的端到端证据。

### 第二级：扩展到 10 键

模块槽连接器为通孔封装，各脚在模块 PCB 焊接面可直接引出（**待实物确认，属 E-01 的附带观察项**）。据此可从连接器脚引出所需 GPIO，扩展至 D-pad 4 ＋ ABXY 4 ＋ L/R 2 共 10 键。

代价：需自写驱动。但本项目本就要写固件，不构成新增成本。

### 第三级：产品化的自制模块板

按官方交互模块与手柄模块的做法（板上无 MCU、无 I²C 扩展器，裸器件直连槽位 GPIO），自制模块板的物料为：

- 与模块槽匹配的连接器
- 轻触开关
- 一颗 EEPROM（用于被 BSP 的模块管理器识别；**空白 EEPROM 会 ACK 并被判为 PRESENT，但描述符 INVALID、正常 claim 不合格**，镜像内容与预烧写属 D2）
- 与底座对接的接口件

**可以不用 MCU、不用 I²C 扩展器、不用电源 IC。**（2026-09-21 按 Hiro H0 F05 整改）原写「无 MCU、无 I²C 扩展器、无电源 IC」是绝对化表述，已改为「可省」：GPIO 数量足够只说明这些器件**可以省去**，**不证明它们必然无价值**；走线数、对接触点数、ESD／串阻与底座侧布局仍可能反过来使其有价值。器件与工艺属嘉立创常规能力范围（**具体可采购性与贴装能力仍须 Chrome 在 T04 中以工厂实际结果确认，本文不作承诺**）。

## 5. 风险与限制

| 项 | 说明 |
| --- | --- |
| **样本唯一** | 用户只有一个交互模块。飞线前须拍照记录原状，优先采用可逆接法（加焊排针或夹具），避免切断走线等不可逆操作 |
| 第一级只验证链路 | 按键行程、十字帽支点、握持落点等手感问题不在其验证范围，仍需 3D 打印件迭代（对应 T17） |
| 模块引脚可及性未证实 | 第二级依赖「连接器各脚在模块 PCB 上可引出」，**未经实物确认** |
| **连接器仍承受非插拔载荷（2026-09-21 按 Hiro H0 F04 新增）** | 即使常驻不拔，连接器仍承受**装配插拔与对位、运输与使用中的振动、来自底座对接方向的侧向载荷与力矩**。**「插拔次数低」不能替代承力与寿命等级的验证。** 须由后继结构设计验证保持力、支撑（是否需要独立机械固定分担载荷）、维护拆卸路径、对接顺序与端口可达性 |
| **几何与选型未定（2026-09-21 按 Hiro H0 F04 新增）** | E-01 的几何决定插接方向与顺序、固定方式、整体外形厚度与 USB-C 避让；**未选定具体连接器件，任何寿命等级与保持力都不能保证**。本轮不画结构，仅登记验证项 |
| **「插一次不拔」尚未确认（2026-09-21 按 Hiro H0 F04 新增）** | 该使用方式与摄像头换槽（UD-A）、维修与返修存在冲突，**尚不是已确认的使用方式**，须用户确认后才能作为结构前提 |
| 常驻模块的机械后果 | 模块常驻会改变整体外形与厚度，影响底座模块仓设计；模块与底座接口的位置、承力与散热均未评估 |
| 对接接口的电流能力 | 底座经该接口给整机供电并充电，所需电流与接口额定值的匹配**未评估**，属 Chrome。**模块槽 pin17 的电压容差、持续／峰值电流、浪涌与反灌边界仍为 unknown，不以任何预算数字代替额定** |
| 原生 USB-C 可达性 | 常驻模块与底座仓是否仍留出 USB-C 插头空间，**需结构证据**，不能由布局方向直接推出 |
| 官方驱动只报 2 键 | 第一级只能得到 2 个按键事件；10 键需第二级与自写驱动 |

**验证项归属**：E-01 的形态确认、承力与保持力、维护拆卸与 USB-C 可达性，属 Chrome 后继者在后续结构与接口条件中列项；本轮不要求完成结构设计，也不因此停止按 `docs/DECISIONS.md` 的 D-017 带假设起草。
