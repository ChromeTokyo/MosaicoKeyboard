# 方案 G：改造模块作为「常驻转接件」

- 日期：2026-09-20；提出：用户，整理：Claude（主控），实际模型 `claude-opus-5`。
- 定位：**产品与结构方向提案，不是硬件技术结论。** 连接器选型、寿命、力学与电流由 Chrome 判定，Hiro 复核。本文不含任何工程尺寸或额定值。

## 1. 起因：两个未解问题

- **耐久**：模块槽连接器（V1.0 原理图标注 `B-2200R20P-B120`，形似 2.54 mm 排针排母）是为「偶尔更换模块」设计的，插拔寿命通常在几十至几百次量级。底座是每天插拔的用途，年均上千次。**这是用途与设计寿命的错配，不是把结构做结实能解决的。**
- **USB-C 被埋**：方案 E 旋转 90° 后，USB-C 落到贴着按键区的那一对面上，无法暴露（见 `review/claude/option-e-rotated-slot.md` 及其缺陷补记）。

## 2. 方案

```
Mosaico ──[模块槽连接器，装配时插一次，此后不拔]── 改造模块 ──[适合频繁对接的接口]── 底座
```

- **模块槽这一端**：改造后的模块常驻插在 Mosaico 上，插拔次数≈1，**寿命问题消除**。
- **模块与底座这一端**：由模块另一面引出适合频繁对接的接口（弹簧针、磁吸或其他，选型属 Chrome）。此类连接器的额定插拔寿命普遍高于机械排针若干个数量级。
- **Mosaico ＋ 模块作为一个整体**从上方落入底座。
- **USB-C 位于与模块槽垂直的另一对面上，保持暴露**——方案 E 的 USB-C 死结一并解除。

## 3. 关键性质：对 E-01 不敏感

`E-01`（V1.2 的模块连接究竟是轴向对插的排针排母，还是磁吸侧向触点）是当前最关键的未知。但本方案在两种情况下都成立：

| E-01 的答案 | 对方案 G 的影响 |
| --- | --- |
| 轴向排针排母 | 常驻插入，插拔次数≈1，寿命无虑 |
| 磁吸侧向触点 | 常驻吸附，寿命更优；对位由磁吸自完成 |

**这是目前唯一一个不依赖 E-01 结论的方案。** 其他方案（A′ 的 UART＋MCU、E 的旋转轴向插、F 的底座接管 USB）都会因 E-01 的某一个答案而失效或需重新裁决。

## 4. 魔改的三级路径

### 第一级：到货当天，零固件改动

官方交互模块（实物丝印 `ESP-Mosaico Module-Interaction V0.2`）的两片输入区为**电容触摸焊盘**。BSP 的触摸模式头文件写明该输入同时检测「手指**以及机械按键对地短路**」。

因此：**从两片焊盘各引一根线到外接轻触开关，另一端接 GND。** 官方驱动原样识别为触摸事件，**固件无需任何改动**，即可验证「物理按键 → 模块 → BSP → 应用」整条链路。

价值：这条链路的验证**完全不依赖底座 PCB、不依赖机械设计、不依赖任何冻结尺寸**，是目前可最早取得的端到端证据。

### 第二级：扩展到 10 键

模块槽连接器为通孔封装，各脚在模块 PCB 焊接面可直接引出（**待实物确认，属 E-01 的附带观察项**）。据此可从连接器脚引出所需 GPIO，扩展至 D-pad 4 ＋ ABXY 4 ＋ L/R 2 共 10 键。

代价：需自写驱动。但本项目本就要写固件，不构成新增成本。

### 第三级：产品化的自制模块板

按官方交互模块与手柄模块的做法（板上无 MCU、无 I²C 扩展器，裸器件直连槽位 GPIO），自制模块板的物料为：

- 与模块槽匹配的连接器
- 轻触开关
- 一颗 EEPROM（用于被 BSP 识别）
- 与底座对接的接口件

**无 MCU、无 I²C 扩展器、无电源 IC。** 器件与工艺属嘉立创常规能力范围（**具体可采购性与贴装能力仍须 Chrome 在 T04 中以工厂实际结果确认，本文不作承诺**）。

## 5. 风险与限制

| 项 | 说明 |
| --- | --- |
| **样本唯一** | 用户只有一个交互模块。飞线前须拍照记录原状，优先采用可逆接法（加焊排针或夹具），避免切断走线等不可逆操作 |
| 第一级只验证链路 | 按键行程、十字帽支点、握持落点等手感问题不在其验证范围，仍需 3D 打印件迭代（对应 T17） |
| 模块引脚可及性未证实 | 第二级依赖「连接器各脚在模块 PCB 上可引出」，**未经实物确认** |
| 常驻模块的机械后果 | 模块常驻会改变整体外形与厚度，影响底座模块仓设计；模块与底座接口的位置、承力与散热均未评估 |
| 对接接口的电流能力 | 底座经该接口给整机供电并充电，所需电流与接口额定值的匹配**未评估**，属 Chrome |
| 官方驱动只报 2 键 | 第一级只能得到 2 个按键事件；10 键需第二级与自写驱动 |

## 6. 当前方案格局

| 方案 | 状态 |
| --- | --- |
| A | 不成立（V1.2 无背部四焊盘） |
| A′ | 可行但不解决按键；走 UART 需加 MCU，违反既有约束 |
| B | 仍可能，需拆机 |
| C | 已否决（侧向盲插） |
| D | 电气成立，缺机械落地方式 |
| E | D 的机械解法之一，**但 USB-C 被埋，有硬缺陷** |
| F | 底座接管 USB，**违反 README 明文要求且损失 OTG／host 能力，需用户裁决** |
| **G** | **D 的机械落地方式，且不依赖 E-01。当前主控首选。** |

**技术判定权仍属 Chrome。** 本文不构成选型结论，不得据此冻结任何设计。
