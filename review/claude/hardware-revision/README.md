### 2.1 官方 1.2.1 期资料中的两项观察（2026-09-20 晚补；2026-09-21 按 Hiro H0 F02 整改收窄）

官方 V1.2 期资料本身（`references/official-v12/`，归档时间晚于本文初稿）提供两项观察。**原小节标题「更强的证据」与其论证方式已按 Hiro H0 报告 §3 的证据表逐行收窄**：线图只限于其所画内容，内侧取电流程不再充当排除证据。

1. **官方《扩展指南 1.2.1》底板外侧线图——限于该页所画内容。** `expansion_v121_zh.pdf` PDF 第 3 页（印刷页码 02）步骤 1「拆下底板上的四颗螺丝」所示为底板外侧，画有四角螺丝孔、两组 2×10P 通孔阵列、一排 7 个圆角矩形焊盘，**中央未画 V1.0 的四圆点**；7 个焊盘的位置与 `v12-assembled-back.png` 一致。**边界**（2026-09-21 按 Hiro H0 F02 整改）：这是对「指南所描绘的外观」的直接证据，**不得把「图上没画」写成「官方明文取消该组焊盘」，也不得当作完整布线证据**——该图为无标注示意图，不声明穷举，亦未给出与 BaseBoard 丝印版次的对照。对拍摄样本而言，清晰裸板照片比未标焊盘的示意图更直接；来源是官方并不能消除图种与版次的限制。
2. **官方提供的一种扩展取电路径（不作为排除证据）。** 同文 PDF 第 4 页（印刷页码 03）步骤 5 所示为底板内侧，焊盘丝印 `5V-I`／`3V3`（BTB 连接器上方）与 `GND`／`VBAT5V-O`（BTB 连接器下方），并注明「新接入硬件的双绞线，可从底板缺口处穿入」；即官方给出的一条扩展路径是拆四颗螺丝、焊内侧焊盘、线从顶边缺口穿出（另见 `references/official-v12/README.md` 与 `exp_backplane.png`）。**此处仅登记为「一种官方扩展路径」。**（2026-09-21 按 Hiro H0 F02 整改：原句「若外侧仍有 I²C＋电源四焊盘，官方不会把扩展流程设计成必须拆机」是反事实推论，**已删除**——官方提供一种拆机焊接方法，并不意味着不存在其他接口，该句不能作为「外侧接口不存在」的排除证据。）

综合上述两项与裸板图像的可见区域观察，本文只维持第 1 节的统一表述与 ASSUMPTION，**不升级为「V1.2 无背部四扩展焊盘」的全版次判断**。官方示意图无标注、无版次对照，第三方实拍不能覆盖整板。置信度维持 derived；实物到货后按测量手册第 0 节读版本并目视背面，所得结论的适用范围限于**该目标样本**。

另三条从实拍得到的观察（均为 derived，须实物确认）：

- **2×10P 通孔已被焊锡填满。** `v12-baseboard-back.png` 中两组通孔呈实心银色，非空孔。若属实，方案 B「对背面通孔做垂直 Pogo 接触」面对的接触面形态与官方 V1.0 图不同。
- **四角银色金属块嵌在外壳里，不在 PCB 上。** 同图四角的银色块位于白色外壳角部凹槽内，PCB 四角只有螺丝孔。其性质（磁铁或结构件）仍未证实。
- **BaseBoard 本身就是整机后盖板。** 官方扩展指南步骤 1、2 与实拍一致：拆四颗螺丝即可把 BaseBoard 整块取下，其外侧贴标签面就是整机背面。本文第 2 节初稿把「整机背盖」与「BaseBoard 背面」当作两个独立对象的表述不准确，已随上表更正。

### 2.2 版本标识的三套口径与 eFuse variant 多对一映射（2026-09-21 按 Hiro H0 F02 整改新增）

本项目会遇到三套互不等价的版本标识，**三者之间的对应关系官方未说明，一律记 unknown**：

| 口径 | 载体 | 本轮已知 | 关系 |
| --- | --- | --- | --- |
| BaseBoard 丝印版次 | BaseBoard PCB 丝印（`V1.2`＋日期码 `260821`） | 第三方裸板实拍可读 | 与下两者的对应关系 **unknown** |
| CoreBoard eFuse `variant` | CoreBoard 芯片内 eFuse，经 BSP 读取并打印 | 见下方多对一映射 | 与上下两者的对应关系 **unknown** |
| 官方指南版次 | 《扩展指南》文件名「仅适用于 1.2.1 版本及以上」 | PDF 第 2 页只声明适用范围，**未给出与丝印或 eFuse 的对照表** | 与上两者的对应关系 **unknown** |

**eFuse variant 是多对一的软件分组（来源：Hiro H0 报告 §3 与 §2 的补充一手源码 E1）。** E1 为官方 BSP 固定提交 `392860b1d1a123c3377947074b2af1f600e86c5d` 的 `components/esp-mosaico-bsp/onboard/esp_mosaico.c`（该文件不在本仓库 `review/chrome/D1-module-interface/evidence/bsp/` 归档的 12 份文件内，由 Hiro 另行核取）。其 `:33–58` 段落中（Hiro 报告 §3 正文记 `:33–58`，其证据表另记 `:43–58`，此处以正文行号为准，实际以该固定提交的源文件为准）：

- eFuse 读出的 **`1.1` 与 `1.2` 都映射为同一个枚举值 `BSP_BOARD_VARIANT_V1_2`**；
- 其他未列值返回错误；
- 该 variant **既不读取 BaseBoard，也不含 patch 版号**。

由此得出两条必须遵守的规则：

1. **本样本观察与全版次结论必须分开。** 到货后即使三个数值彼此相符且目视未见四焊盘，也只确认**该目标样本**的观察，不能升级为「全部 V1.2 出货板」的结论，更不能推出「BaseBoard `V1.2` 等于指南 `1.2.1`」的版次等价。
2. **采集时必须同时保存两个字段**：启动日志中 **eFuse 的原始 `vX.Y` 字符串**，与 **BSP 映射后的 `variant` 枚举值**。二者不是同一字段；只记其中一个会把多对一映射的信息丢掉，导致 `1.1` 的板被当成 `1.2` 的板。

## 3. 调试焊盘变化的含义

V1.2 的背面焊盘从「3V3 + UART + BOOT + EN」变为「**5V** + UART + BOOT + **RST** + 双 GND」。

- **得到**：按丝印，该组焊盘含 `5V` 与两个 `GND`，且 `RX`/`TX`/`BOOT`/`RST` 齐备——形态上支持「不拆机供电并烧录」。**丝印不等于电气定义**：官方未公开这 7 个焊盘的电气定义与额定值，通断、保护与限流均待实物核查。
- **失去**：**这一组 7 个焊盘的丝印中没有 I²C**（2026-09-21 按 Hiro H0 F02 整改：原句「背面**没有 I²C**……该路径在 V1.2 背面不存在」是对整个背面的排除断言，超出「该组焊盘丝印」的观察范围，已收窄）。本项目原设计用 I²C IO 扩展器读按键并经背部触点上行，该路径在这组焊盘上没有对应引脚；背面其他位置是否另有 I²C 引出未经排除，见第 1 节的统一表述。

按上述限定范围：V1.2 的背面 7 焊盘适合作为「供电 + 烧录」接口的候选，**不能**从中取按键输入。按键输入须另找通路（不因此断言背面全无可能，只是本次设计不依赖它）。

## 4. 交互模块实物确认

录屏中清晰可见模块丝印 **`ESP-Mosaico Module-Interaction V0.2`**，与 BSP 源码中的 `MOSAICO_BOARD_TYPE_INTERACT = 0x16` 对应。板上可见：

- **两片大面积金色棋盘状焊盘＝电容触摸电极**（不是机械开关）
- 6 颗 WS2812、红外发射管、PIR、光敏电阻、四角安装孔
- 设备屏幕同时运行官方 demo：`Module-Interaction` / `LED 0–3` / `TOUCH` / `IR` / `PIR MOTION` / `LDR 59%`

**关键**：BSP 的触摸模式头文件写明该输入同时检测「手指**以及机械按键对地短路**」。官方设计本就允许在这些焊盘上接机械开关——这使「把交互模块改造成按键输入板」在电气上顺理成章。
