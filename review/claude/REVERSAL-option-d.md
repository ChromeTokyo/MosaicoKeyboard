# 方向更正：方案 H 降级，回到方案 D（模块槽）

- 日期：2026-09-20；作出更正：Claude 主控，实际模型 `claude-opus-5`。
- **这是同一天内对同一问题的第二次方向更正，且推翻的是几小时前刚被用户确认的方案 H 与需求修订 R04。**

## 1. 更正的结论

**方案 H（背面撞针 ＋ 底座 MCU ＋ UART）应降为备份；方案 D（做成插模块槽的模块）恢复为主线，其机械落地方式为方案 G（常驻转接件）。**

**需求 R04 允许底座使用 MCU 的修订不再必要**，建议回退为「不使用第二颗可编程 MCU」，或保留为可选但非必需。**该回退属需求层面，须用户决定。**

## 2. 依据：三项新证据，均为 confirmed

### 2.1 V1.2 给模块槽配了一条独立 I²C 总线

BSP 源码 `components/esp-mosaico-bsp/onboard/esp_mosaico.h:63-75`：

```
#define BSP_I2C_SDA_V1_0          GPIO_NUM_0
#define BSP_I2C_SCL_V1_0          GPIO_NUM_1
#define BSP_I2C_SDA_V1_2          GPIO_NUM_56
#define BSP_I2C_SCL_V1_2          GPIO_NUM_3
/* v1.0 shares I2C with the mainboard; v1.2 uses a dedicated I2C1 bus. */
#define BSP_SUBBOARD_I2C_PORT_V1_0 I2C_NUM_0
#define BSP_SUBBOARD_I2C_PORT_V1_2 I2C_NUM_1
#define BSP_SUBBOARD_I2C_SDA       GPIO_NUM_0
#define BSP_SUBBOARD_I2C_SCL       GPIO_NUM_1
```

**V1.0 时主板与模块槽共用 I²C；V1.2 把主板总线搬到 GPIO56／GPIO3，把 GPIO0／GPIO1 整条留给模块槽，跑在 `I2C_NUM_1` 上。**

直接后果：此前反复引用的「共享总线已占用 `0x11 0x12 0x19 0x55 0x5A 0x69`」这条约束**在 V1.2 上不成立**。模块总线上只有 `0x50`／`0x51`，底座选址几乎不受限。

代价（也已确认）：腾出 GPIO56 与 GPIO3 的代价是砍掉 V1.0 的 codec 电源控制脚与状态 LED，两者在 V1.2 上分别变为 always-on 与不可用。

### 2.2 模块槽本来就同时提供 I²C、5V 供电与充电、以及足量 GPIO

模块槽 pin16／pin14 为 `GPIO0`＝SDA ／ `GPIO1`＝SCL；pin17 为 `5V_IN`，官方引脚表注明「External 5 V input (can power and charge the device)」。左槽 12 根 GPIO 中扣除作 EEPROM 地址选择的 `GPIO14` 后仍有 11 根，足够 D-pad 4 ＋ ABXY 4 ＋ L/R 2 共 10 键各占一根。

左槽的 GPIO 与板载音频 I2S **零冲突**；右槽的 GPIO49／52／54／37／40 与 I2S 复用，占用会使扬声器与麦克风失效。**因此底座应固定使用左槽。**

MakerWorld 模型页外壳实拍图上，中框模块槽正上方印有逐脚引脚标签，与 V1.0 用户指南的 H2 表**逐脚一致**，说明 2×10P 的引脚定义在 V1.2 上未改。

### 2.3 背部焊盘在 BSP 中没有任何软件支持

对 BSP 全部 32 个 commit 执行 `git grep`（back pad／pogo／rear pad／expansion pad／4-pad／磁吸／260710／260821）**零命中**。背部焊盘从来没有软件支持；其用途只能靠万用表实测确定。

## 3. 我错在哪

方案 H 的出发点是「V1.2 背面没有 I²C，所以按键要走 UART，所以需要 MCU」。这个推理链本身没错，**错在前提选择**：我把「背面」当成了唯一通路，而**官方专门为扩展准备的接口是模块槽**，那里 I²C、供电、GPIO 一应俱全，V1.2 还特地给它配了独立总线。

**我绕开了一个为此而设计的接口，然后为了绕开它而增加了一颗芯片，并据此让用户修订了需求。**

直接原因是检索顺序：我先用第三方照片确认了「背面四焊盘消失」，随即把注意力锁死在背面，而没有先去读 BSP 源码里模块槽在 V1.2 上发生了什么。**新证据出现时应当重新检视前提，而不是在既定前提上继续推演。**

这是同一天内第二次方向更正，也是本会话第五个已记录的错误（前四个为 3mf 来源判断错两次、摄影测量标定方向用错、焊盘直径混轴）。

## 4. 更正后的方案格局

| 方案 | 状态 |
| --- | --- |
| A | 不成立（V1.2 无背部四焊盘） |
| A′ | 降为备份：背面 7 焊盘可作供电与烧录的兜底通路，但无 I²C |
| B | 与官方扩展指南的「拆底板焊内侧焊盘」路径重合，**与「不拆解、不焊线」约束冲突**，仅作兜底记录 |
| C | 已否决 |
| **D** | **主线。** 做成插左槽的模块：I²C（V1.2 独立总线）、`5V_IN` 供电与充电、11 根可用 GPIO、烧录口，一个槽全齐 |
| **G** | **D 的机械落地方式。** 改造模块常驻插在 Mosaico 上，模块另一端以适合频繁对接的接口与底座相连 |
| E／E′／F | 不再需要 |
| H | **降为备份。** 若 D 因机械原因不可行再启用 |

## 5. 随之变化的事项

| 项 | 变化 |
| --- | --- |
| 需求 R04（允许底座 MCU） | **不再必要，建议回退，须用户决定** |
| 给 Chrome 的第二批派发 C1（H-01 UART0）、C2（H-02 5V 焊盘载流） | **作废**，它们只服务方案 H。已另行改派 |
| 底座是否需要 I²C 扩展器 | 不需要。按键直连 GPIO，按官方模块做法 |
| 底座是否需要 EEPROM | **需要**。一颗 AT24C02，地址 `0x50`（左槽，`GPIO14` 拉低选中），用于被 BSP 识别 |
| 按键读取方式 | 轮询，20–40 ms。BSP 三个官方模块驱动全部为轮询，模块管理器热插拔检测为 250 ms 轮询 ＋ 3 次去抖，**没有任何中断通路** |
| 实物到货第一步 | 刷任意 BSP 示例看串口日志，TAG `S31-Mosaico` 会打印 `Hardware version: vX.Y (variant=v1.N)`，从 eFuse 读出 variant。**（2026-09-21 更正，Hiro 在 H0 复核中指出）原写「直接读出真实版本，比任何照片判读都可靠」已撤回**：`onboard/esp_mosaico.c` 把 eFuse 1.1 与 1.2 都映射到 `variant V1_2`，只有 `V1_0`／`V1_2` 两档分辨力，**不能分辨 1.2 与官方指南所称 1.2.1**，也不能证明 CoreBoard 与 BaseBoard 同版；须与两块板的丝印、日期码并列登记 |

## 6. 仍未解除的未知

- 模块槽连接器的机械形态与插拔特性（对应 `E-01`）。方案 G 对此不敏感，但仍需实物确认。
- 模块 PCB 上连接器各脚是否可引出（第二级魔改的前提）。
- `5V_IN` 的实际载流能力：官方文字称可供电并充电，但**未给电流数值**。
- eFuse 中的 board variant 烧在 CoreBoard 的芯片里，而用户看到的 260710／260821 是 **BaseBoard** 日期码，两者是否严格对应，源码无法证明。**且 variant 只有两档（1.1 与 1.2 同映射 `V1_2`），本身也分辨不出 1.2 与 1.2.1。**

## 7. 本文性质

**证据整理与方向更正建议，不是硬件技术结论。** 技术判定权属 Chrome，需求回退决定权属用户，独立复核属 Hiro。本文不得据以冻结任何设计。
