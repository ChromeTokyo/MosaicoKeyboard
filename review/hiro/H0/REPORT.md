## 3. (a) 降级恰当，但必须收窄命题

### 三个直接回答

1. **推导：维持 derived，不恢复 confirmed，也不必降到“不能起草”。** 裸板图可读 `V1.2 / 260821`，原 V1.0 四触点的中央区域未见四焊盘，这是对该图的直接观察。它不能证明板周遮挡区域、所有 V1.2 出货板、或所有可能的 I²C 引出点都不存在。`review/claude/hardware-revision/README.md:12–14,48–50` 把局部观察扩大成全版次和功能排除，应改。
2. **实际检查＋推导：官方线图可作重要旁证，不能单独作为“V1.2 实物取消四焊盘”的主要定论依据。** PDF 第 3 页步骤 1 确实画有两组 20P 阵列、一排 7 个触点，中央未画 V1.0 四圆点。对“指南所描绘的外观”这是直接证据；对实物是否遗漏细节、对 V1.2 是否适用均是推导。对拍摄样本，清晰裸板照片比未标焊盘的示意图更直接；来源是官方不能消除图种与版次的限制。
3. **未检查／unknown：不能证明 BaseBoard `V1.2` 等于指南 `1.2.1`。** PDF 第 2 页只声明适用 1.2.1 及以上，没有给两者对照。**实际检查 E1:33–58：eFuse 的 1.1 和 1.2 都映射为 `BSP_BOARD_VARIANT_V1_2`；其他未列值返回错误。** variant 是软件分组，既不读取 BaseBoard，也没有 patch 版号；打印值不能证明指南对应。到货记录三值有用，但“相符且无四焊盘”最多确认该样本观察，不能升级全版次或版次等价结论（派发包 `docs/handoffs/claude-to-hiro.md:183,186`）。

建议统一采用：**“现有 V1.2／260821 图像未见 V1.0 中央四触点，官方适用 1.2.1＋的示意图亦未画出该组；两种版次口径关系未知。ASSUMPTION: 本次设计不依赖旧背部四触点，到货后核对目标样本。”** 这是限定范围的设计前提，不等同于证实全部背面没有 I²C。

## 4. (b) 方向更正有用，必要性与排他性被写过头

**推导：**D 值得恢复为优先方向。固定 BSP 的左槽有足够 GPIO，模块 I²C 有明确初始化支持；V1.0 官方接口还定义供电输入。它推翻的是“只能经背面 UART 才能输入按键”的限制，不是证明 H 不可行。即使 (a) 最后改变，模块槽仍值得考察；D 的价值也不只来自独立 I²C，旧版共享总线不自动否定模块方案。

### D＋G 继续起草前应明确的条件

- **推导，UD-A 仍由用户决定：**SH:19–39 与 `BSP_AND_EEPROM.md:25` 的摄像头左槽约束说明会有槽位竞争，但不是技术上必须否决 D。若接受摄像头分时使用，左槽合理；若要求同时使用，应另评架构。右槽 5 个 I²S 复用脚限制“十键一键一 GPIO”，不等于一切右槽方案都会损失音频。H0 不替用户选择。
- **推导，UD-B 仍由用户决定：**D 能免第二 MCU，不等于应撤销用户已授权的 MCU 选项。`REVERSAL:10,75` 保留用户裁决是对的；固件成本／对接触点数量等仍会影响取舍。GPIO 数量足够也不证明 I²C 扩展器必然无价值。这里只保留设计选择，不重做电路。
- **推导，G 降低拆插次数而非消除机械依赖：**`option-g-resident-adapter.md:7–35` 的“寿命问题消除”“磁吸自对位”“唯一不依赖 E-01”无充分依据。即使长期不拔，连接器仍承受装配、振动、侧向载荷；几何决定插接、固定、外形与 USB-C 避让。未选具体件，不能保证寿命等级。降为 ASSUMPTION，并由后继结构设计验证保持力、支撑、维护拆卸、对接顺序及端口可达性，不在本轮画结构。
- **未检查：**“插一次再不拔”尚不是已确认的使用方式，尤其与摄像头换槽／维修冲突。H 不能只在“D 机械失败”时才恢复；若槽位需求或供电边界不能满足，也应重评。原生 USB-C 保持可达仍需结构证据。

**实际检查：**逐字段对照 `BSP_AND_EEPROM.md:39–61` 与 M:199–260，无偏移差异。三段受保护数据及 CRC 分别为：`[0x00,0x34)` 52＋2 字节、`[0x36,0x3E)` 8＋2、`[0x40,0x84)` 68＋2；合计 134。第三段包括 `param_version`（0x40，2 字节）、`param_length`（0x42，2 字节）和固定 64 字节参数区，不随有效长度缩短。

**实际检查＋推导：**源码逐字节异或、LSB-first、初值 FFFF、反射多项式 A001、无最终异或，是 CRC-16/MODBUS 参数组合。独立按这些参数计算 ASCII `123456789` 得 `0x4B37`；CRC 在镜像中以 little-endian 读取。这是算法与格式交叉核算，不是 C 解析器运行测试，也不证明 EEPROM 选型、电气或镜像身份分配已完成。
