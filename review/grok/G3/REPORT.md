## 发现

### PR #51 — D2 / D3 / J1 / D4

#### G3-01　高　升压备选电阻与公式矛盾

`origin/claude/design-d/dock-board` @ `8068ce2` 的 `hardware/dock-board/POWER_TOPOLOGY.md` 写：`VOUT = VREF × (1 + R1/R2)`，`VREF = 595 mV`，`R_FB2 = 120 kΩ`，`R_FB1 = 909 kΩ` → 5.10 V；同段又写把 `R_FB1` 改成 `768 kΩ → 5.16 V`、`750 kΩ → 5.06 V`。`POWER_BUDGET.md` 把「768 kΩ（5.16 V）」和「不得超过 5.25 V 空载上限」又写了一遍。

本会话重算（R2 保持 120 kΩ）：

| R_FB1 | VOUT |
| --- | --- |
| 909 kΩ | 0.595 × (1 + 909/120) = **5.102 V** |
| 768 kΩ | 0.595 × (1 + 768/120) = **4.403 V** |
| 750 kΩ | 0.595 × (1 + 750/120) = **4.314 V** |

要得到 5.16 V / 5.06 V，同公式需要的 R_FB1 约为 **920.7 kΩ / 900.5 kΩ**，不是 768 / 750。

更强的一点不依赖 0.595：在 R2 固定、VREF > 0 时，VOUT 随 R1 增大。768 kΩ < 909 kΩ，输出必须低于 909 kΩ 那一档，不可能从约 5.10 V 升到 5.16 V。Chrome 的 4.403 / 4.314 复算成立。这些数仍然不是已批准的 pin17 电压。

#### G3-02　高　USB-C 输入限流没有跟着源的广告电流走

同一 `POWER_TOPOLOGY.md`：CC1/CC2 各 5.1 kΩ 到地；`R_ILIM_CHG = 1.1 kΩ`；`IINmax = KILIM / RILIM`，KILIM typ 1610（1500–1720）A·Ω；(EN2, EN1) = (1, 0) 为电阻设限。重算：

- 1610 / 1100 = **1.464 A**
- 1500 / 1100 = **1.364 A**
- 1720 / 1100 = **1.564 A**

「约 1.46 A，系数上沿约 1.56 A」与原文一致。原理图文字只有 Rd 和这颗固定电阻，没有读取 CC 电压再改限流的硬件。Rd 把设备标成 Sink，并不等于源正在广告 1.5 A 或 3 A。本会话没有重下 USB-IF PDF；这个结论来自底座提案自己的接法，不是来自对规范条文的重新引用。2 A 保险丝在原文里也写明不参与正常限流。B5「仅 USB、无电池、约 1.1 A @ 5 V」建立在这颗固定 1.46 A 上，源能力未判定之前不能当规格。

#### G3-03　中　5.10 V 空载带本身也不闭合

提案把 909 kΩ / 120 kΩ 的空载范围写成 4.93–5.27 V，同时又要求空载不超过 5.25 V。只让 R_FB1 ±1%、R_FB2 固定、VREF 取 0.580/0.610 V 时，本会话得到约 **4.930–5.277 V**，和提案的 4.93–5.27 同一路算法。若两颗电阻独立 ±1%，同公式的角点约为 **4.887–5.324 V**。5.25 V 上限低于提案自己的 5.27 V，也低于这个更全的角点。Chrome 指出了 5.27 与 5.25 的自相矛盾，没有把双电阻独立公差摊开。这不推翻 G3-01，只说明 5.10 V 档的上下限还不能冻结。

#### G3-04　高　WP 验收没有判别力，默认态仍可写

`hardware/eeprom/PROGRAMMING.md` 第 7.5 节要求改桥后重跑方法 a：写入应 ACK，回读应与改桥前完全一致。当前镜像就是要写进去的那一份。WP 真生效和 WP 失效时，回读都可以相同。写事务 ACK 也不能当保护证据：8871F 引脚表写明 WP 接 VCC 时写入被禁止。Chrome 指出的「先读未用字节再写反码」针对的是这个洞。当前格式只用 0x00–0x85（134 字节）；0x86 是下一字节。这只对当前格式成立。

同一文件写明 ICD 拟默认写保护，而模块板 `netlist.yaml` 的 `JP1.default_bridge` 是 `[1, 2]`（WP→GND，可写）。8871F Note 1：A0/A1/A2/WP 不驱动时内部下拉，所以空桥也是可写。D2 报告把这列为必须改唯一电路源，本复核同意，并且没有看到 #51 改掉 Claude 的电路源。

#### G3-06　中　J1 的 8.5 mm 不是这颗公头的轴向塑胶深；配合仍未知

- `C124406_Ckmtw.pdf`：`9aaf464aa81271f10be0ff7ae8dce64d20964e03e05e67b2758d779f11cd3dba`，544021 字节，1 页

#### G3-09　高　假绿属实，补丁把它改成失败

在 `3eb5cf8` 的旧脚本上，替身 OpenSCAD 对每一项都打印 `Ignoring unknown module 'shell_front'`：15/15 为 `n/a`，脚本仍打印「✓ 全部通过：15 项」并 **EXIT 0**。只回显 `MOSAICO_W` 时，旧的跨分支脚本列出 **22** 条「警告（不阻断）」，仍打印「✓ 全部通过：16 条等值、6 条包含、1 条供需」并 **EXIT 0**。成功句把没有检查到的关系也算进了通过数。

同一替身跑 #50 头：fit **EXIT 1**（0 条判定失败、15 条未判定）；cross **EXIT 1**，并打印「实际检查：等值 1/16，包含 0/6，供需 0/1」和 22 条阻断。

仓库里的 8 个测试覆盖了：未知 module 使整门失败、非零退出拒绝空结果标记和实心标记、无 STL 也无空标记则是 error、fit 超时是 error、15 项都得到与表一致的结果时可以 EXIT 0、缺必需键失败、非零退出拒绝完整但过期的 ECHO、23 个键一致时可以 EXIT 0。本机 `unittest` 8 项全部通过。fail-closed 的主声称成立：缺模型、编译失败、超时、没有有效 STL、缺契约键都不能成功；成功路径要求每一项都有与期望一致的判定。

#### G3-10　中　测试通过不等于几何通过

8 项测试的 OpenSCAD 是脚本里的假可执行文件。成功用例里，含 `translate([0,-0.20,0]) modsolid()` 或 `translate([0,-0.10,0]) top_frame()` 的片段保持非空 STL，其余删掉 STL 并打印空对象。这只证明检查器在「每项都符合 CASES 表」时返回 0。那两项期望 `solid` 的用例是「应当接触」，不是「应当无碰撞」。

G2 在真实模型上的结论仍是：fit 两处失败（上压框∩模块名义及 −0.30X）加扫掠超时，cross 与 mismate 的 EXIT 0 不包含「5V↔GND 无损」。#50 不发布机械 `.scad`，也不能把 G2-05 收掉。合入 sweep 之后必须用同一 SHA 的真实模型重跑，重跑之前 G2 保持 HOLD。

#### G3-11　低　`WARNING` / `ERROR` 子串会抢在几何判定之前

`check_fit_geometry.py` 在认出未知 module 之后，只要退出码非零，或诊断里出现子串 `ERROR` 或 `WARNING`，就返回 `error`，不再看空对象标记和 STL。`check_cross_branch.py` 在同样条件下丢弃 ECHO。8 项测试没有覆盖「退出码 0、诊断里有 WARNING、同时有有效空对象或有效契约」这一路。真实 OpenSCAD 若在可判定的求交上打印 WARNING，新门会失败。这是比「缺证据」更严的规则。它不会把假绿放回来。合入 sweep 后应用真实 stderr 看一次；若良性警告把本可判定的空/实心打成 error，再收窄匹配，而不是退回「n/a 也算通过」。

跨分支超时和「系统里没有 openscad」在代码里会失败，但 8 项测试只测了 fit 的超时，没有测这两条。覆盖缺口不否定已测到的 fail-closed。
