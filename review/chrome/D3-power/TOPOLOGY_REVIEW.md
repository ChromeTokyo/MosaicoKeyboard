# D3：方案 D 底座电源路径与主控提案复核

2026-09-23 JST；输入 main `96fd823`，审查待合入 `origin/claude/design-d/dock-board` 的 `POWER_TOPOLOGY.md`/BOM/网表；本文件为 Chrome 电气接口意见，不是制造文件或 G3/G6 放行。V1.2 pin17 的实际输入窗口、持续/浪涌额定、pin20 回流能力及主机双 USB 内部合并方式仍 unknown；[D1 原始边界](../D1-module-interface/DOCUMENT_BOUNDARIES.md)与 Hiro H0 F07 适用。

## 必须成立的硬件路径

```text
底座 USB-C 5 V ──输入保护/按源能力限流──┬──充电器 IN──充电控制──电池连接器/保护──底座电池
                                       │            │
                                       │            └──电源路径 OUT──VSYS──硬件欠压允许──升压──BOOST_5V
                                       │                                             └───────────────┐
底座电池──极性/过放/过流/温度保护───────────────充电器 BAT──电源路径 OUT──VSYS────────────┘

BOOST_5V ──输出限流/短路关断──反向阻断──DOCK_5V──模块板 5V_IN──左槽 pin17
DOCK_GND ────────────────────────────────────────────模块板 GND ───左槽 pin20

左槽 pin18 5V_OUT：NC；pin19 VCC_3V3：只由主机输出给 EEPROM，底座不驱动。
```

充电器应有**无电池时仍能由 USB 驱动 OUT** 的电源路径，以便先不接底座电池、模块板和主机，仅用 USB 分级测 VBUS、VSYS、BOOST、限流后和 DOCK_5V。底座电池与主机内置电池绝不直接并联。升压、输出允许和限流的使能只来自本地电压检测/硬件联锁；**不得等 EEPROM、主机 GPIO/I²C、GPIO60 或 MCU 的判断**，否则主机内置电池耗尽时会卡在无法启动的循环。适配器能力检测即使用专用硬件也不得依赖主机软件。

## USB、底座电池、原生 USB 八态（设计期预期，均未实测）

D=底座 USB 有效；B=底座电池可用；N=主机原生 USB 有效。各有电态还要重复主机内置电池“正常/耗尽”、主机“运行/关机”、底座输出“允许/故障关断”的子态；不能只跑以下八行就声称 F07/G6 关闭。

| G6态 | D B N | 底座期望 | 必查边界 |
| --- | --- | --- | --- |
| B1 | 0 0 0 | DOCK_5V 关闭 | 主机内置电池可能仍让信号线带电；断电底座不得被按键/I²C幽灵供电。 |
| B2 | 0 0 1 | DOCK_5V 关闭 | pin17 可能被原生 USB 抬高（V1.2 unknown），从接口回到 BOOST/VSYS/VBAT/底座 USB 的电流须受反向阻断；测电压与方向电流。 |
| B3 | 0 1 0 | 电池→VSYS→升压→pin17；欠压/保护故障时硬件关断 | 低电池、空电恢复、启动浪涌、主机关机时是否受充。 |
| B4 | 0 1 1 | 电池路径可能有输出，主机内部取电优先级 unknown | 两路电流方向；原生 USB 不得给底座电池非受控充电。 |
| B5 | 1 0 0 | **仅 USB、无电池**完成分步上电，能力不足时受限或关断 | 不接主机先量各级，再接假负载，最后接主机；不可假定任意 USB 口支持提案峰值。 |
| B6 | 1 0 1 | 两 USB 并存，底座无电池 | 分别拔任一路，查反灌、瞬态和主机复位。 |
| B7 | 1 1 0 | 先供系统，余量充底座电池；需求超过输入能力时限充/电池补充 | 用独立电流表量净充电、输入能力、温升；不由理想效率推定必净充。 |
| B8 | 1 1 1 | 所有电源并存 | 逐路拔插、输出故障关断/恢复、各路电流方向和温升。 |

主机原生 USB 当 **source** 给外设供电是另一模式，不等于 N=1；G6 应另测。与主机对接前先在无电池的 B5 台架态用假负载验证，之后有电池、双 USB 与异常态逐项升级；记录测试点与故障灯真值。反向阻断要覆盖底座自身升压正常、关断、短路保护动作和电池断开四种状态。pin18 始终 NC；输出禁用时不得通过信号线或 pin19 形成第二供电路径。

## 待审 Claude 电路提案：明确需改处

1. **USB-C 输入限流与供电来源不匹配。** 提案只在 CC1/CC2 放 5.1 kΩ Rd，却把 BQ24074 的 ILIM 固定为约 1.46 A（按其列的系数可达约 1.56 A），并按这个数推导“仅 USB 无电池可供 1 A@5 V”。Rd 使设备成为 Sink，**不会自动判别 Source 当前广告的是默认电流还是 1.5/3 A**；USB Type-C 规范要求需要额外电流的 Sink 监测 CC 并随广告能力调整。BQ24074 有 100/500 mA 与电阻设限模式，但提案没有实现选择逻辑。[USB-IF Type-C R2.4 §4.6](https://e2e.ti.com/cfs-file/__key/communityserver-discussions-components-files/196/USB-Type_2D00_C-Spec-R2.4-_2D00_-October-2024.pdf)、[TI BQ24074 数据表 §7/§9.3](https://www.ti.com/lit/ds/symlink/bq24074.pdf)。通用 Type-C 口须由**硬件**检测广告能力并相应设限，或保守按所有允许源的最低能力设限；若考虑专用适配器，必须以实际接口和受电条件防止普通 USB 口被误当作 1.5 A 源。B5 功率是否够用须据此重算。2 A 保险丝不是输入电流协商或正常工作限流。
2. **升压反馈阻值备选计算错误。** 提案 `TPS61023` 取 `VREF=0.595 V`、`R_FB2=120 kΩ`、`R_FB1=909 kΩ`，按厂家 `VOUT=VREF(1+R1/R2)` 得 **5.102 V**，计算一致；但同段说改 `R_FB1=768 kΩ→5.16 V`、`750 kΩ→5.06 V`，实际分别是 **4.403 V、4.314 V**；`POWER_BUDGET.md` 又转录了该错误。按同公式欲得 5.16/5.06 V，理论 R_FB1 分别约 921/901 kΩ，仍需选标准料并算 min/max。原提案本身算出 909 kΩ 空载上限约 5.27 V，不能同时写成“不超过 5.25 V”。这些值均不得在 pin17 输入窗口未知时定稿。[TI TPS61023 数据表 §8.2.2.1](https://www.ti.com/lit/ds/symlink/tps61023.pdf)。
3. **输入、输出和热额定未闭。** pin17、模块板两针并联与连接焊点的实际载流/压降 unknown，AS-09 的 0.6 A 连续/1 A 峰值仅是预算假设。输出限流 TPS2553、反灌 LM66100 是待审候选；需逐器件核引脚、欠压、反向启动瞬态、最坏短路耗散、恢复方式与额定，不把“有两个IC”当证明。输出过载必须有可观测 FAULT、硬件关断/安全限流与可重复恢复，阈值随主机实测额定和厂家资料定，不凭 V1.0 100 mA/500 mA 借数。
4. **返修与充电温度须进 G3。** 提案充电主芯 BQ24074 是 3×3 mm QFN/裸焊盘；`docs/TEAM_PLAN.md` §6 要求关键器件可更换，不得仅因紧凑采用难返修封装承担关键功能。需证明嘉立创可返修并一次备足整板，或改为可返修封装/模块。BOM 默认 `R_TS_FIX=10 kΩ` 等效常温，**绕过电池温度感知**；只可台架，无电池包 NTC 或等效温度保护前不能装进交付用户的整机。
5. **接口与保护极性仍待实物。** V1.2 pin17 电气路径和输入额定未公开，主机 5V_IN 与原生 USB 的内部二极管/开关不能用 V1.0 原理图推定；pin20 的单点回流额定也未知。装板前需按板号取得厂家资料并做受控台架测量；若拿不到额定，持续标为假设，不能仅靠逐级加负载试验反推出安全额定或冻结输出限流/过冲阈值。同一机的多次 G6 实测不能替代跨批次的厂家额定，仍须非作者工程审查。
6. **网表与几何版本未同步。** 未合入的底座/模块板提案仍按 2×8 接点与该分配计算并联针数；另一个待审几何稿讨论 4×4。旧表里“错位一列只会短路、无损”的说法已被 G2 复核质疑。接点数、极性错位、回流和载流必须在同一冻结几何上重算，不以现有输出限流替代 GPIO 误触安全性。提案引用的 `hardware/dock-board/DESIGN_NOTES.md`/`README.md` 在该分支并不存在，资料交接需补齐或删失效引用。

本轮结论：拓扑方向满足“USB→充电/电源路径→电池/VSYS→升压→pin17”的功能意图，**但 Claude 数值电路为 CHANGES_REQUIRED**。未改 `claude/design-d/dock-board` 的设计源；其 1.46 A、5.10 V、保护阈值和真实输出能力均不是本项目已批准规格。
