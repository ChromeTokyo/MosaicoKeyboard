## F01：POGO_5V 与 BOOST_SW 被错误合并（阻断）

原理图中 U4.3 的导线从 `(180,1890)` 到 `(145,1890)`；L1.2 的导线从 `(210,1890)` 到 `(175,1890)`。两者共线重叠，BOOST_SW 标签锚点 `(175,1890)` 还落在 U4.3 导线上。见输入版本 `design/mosaico-dock-schematic.json` 第 394、412–413 行；生成位置来自 `design/build_design.py` 第 187–193 行。

实际 EDA 网表把 `TP6-1 J3-3 C11-1 U4-6 U4-3 L1-2 U3-5` 全部归入 BOOST_SW，POGO_5V 不再作为独立网出现。逐项比较全部引脚后，误并的 5 个引脚为：

| 引脚 | 设计网络表 | EDA 实际网表 |
| --- | --- | --- |
| U4.3 | POGO_5V | BOOST_SW |
| U4.6 | POGO_5V | BOOST_SW |
| C11.1 | POGO_5V | BOOST_SW |
| J3.3 | POGO_5V | BOOST_SW |
| TP6.1 | POGO_5V | BOOST_SW |

其余已连接引脚与 9 个 NC 的归属对应一致。这是工具解析后的实际网络错误，不只是视觉拥挤，也不是电路性能审核结论。

修复方案：保留原 A0 审查输入，在唯一生成源中调整功能区布局，按符号与连线包络避免相交；重新生成、导入并比较全部 EDA 网表引脚。验收要求为 43 个预期网络、242 个引脚归属全部一致、无意外网合并。不能只比较生成脚本内部的网络表与 CSV。

## F02：PCB 数据格式不被编辑器接受（阻断）

原 PCB JSON 在本地可以解析，原理图通过同一编辑器和文件选择流程导入成功；PCB 的文件入口与源码入口均失败。捕获的浏览器错误日志为空数组，因此没有据错误提示猜测唯一异常原因。

与官方格式及本地数据对照发现以下需要逐项修复的结构问题：

- 84 个封装的 LIB 头 `layerid` 均为 `0`，`uuid` 为空，`utime` 位置放入了 `gge...` 字符串；生成位置为 `build_design.py:240`。
- 共发现 14 组重复 ID：TP1–TP12 的 PAD ID 与各自父 LIB ID 相同，另有 C1 两个 PAD 分别与 C11/C12 的 LIB ID 冲突，需对父子图元使用区分命名空间的唯一 ID；见第 204、232、240 行。
- 48 个本地占位 PAD 的 `holeCenter` 位置为单值 `1`，需按格式核对；197 个缓存 PAD 移动后该坐标没有同步移动，亦需核对。见第 204、216–220 行。
- DRCRULE 使用平铺字段，与当前官方示例的 `Default` 对象结构不同；TEXT 尾部字段也需要按编辑器原生输出校对。

受控诊断仅在证据副本中执行：删除 DRCRULE，或只把 84 个 LIB 的 layerid 从 0 改为 1，分别仍报“数据格式不对”。两者都没有成为成功导入版本。**不能把某一个上述字段宣称为已定位的唯一根因。**

修复方案：以编辑器新建的最小原生 PCB 为格式基准，逐层恢复文档字段、单个封装、PAD、文字和机械图元；修正生成器后再验证全量 84 个器件的导入、编辑、保存、重新打开和网表／焊盘对应。禁止以“删除 DRC 规则后能打开”作为最终检查规则的验收；任何成功诊断副本仍需恢复并审核规则。

## F03：输入缓存与既有输出不同步（阻断可复现基线）

隔离复制 `design/`、`references/` 后运行原生成器两次，均退出成功，同一输入两次输出逐字相同；但与仓库保存的产物不同。

- C1、R20、R21、R22、C5、U8、C7、C8、C9、C14、C15、C16 的占位几何会改为缓存几何；C5/C7/C8 的封装尺寸标识同时变为 C0805。
- 原理图、PCB、设计网络表、BOM 四份文件存在语义变化；引脚 CSV 的 242 行数据语义不变，仅 LF/CRLF 差异。
- R26 引用的 C23239 缓存缺失，仍回退至本地占位 R0603，生成器未硬失败。
- U8 强制封装名称与当前 C55266 缓存名称仍相差 `-BR` 后缀，属于待核对元数据。

修复方案：建立实际引用缓存的版本／哈希清单，显式区分允许占位与必须存在的库，冻结可复现输入后再统一生成。几何变化需作为明确设计变更审查，不把新生成文件静默覆盖原 A0 审查基线。

## 复现

从仓库根目录执行下列命令；`--rebuild-dir` 必须位于仓库外且尚不存在：

```sh
python3 tools/check_a0_static.py . \
  --rebuild-dir /tmp/mosaico-t02-rebuild-UNIQUE \
  --imported-schematic review/chrome/T02/evidence/schematic-import-source.json \
  --native-altium-netlist review/chrome/T02/evidence/a0-eda-altium.net \
  --output /tmp/mosaico-t02-check.json
```

检查器针对当前单页、无旋转的短线生成模式，是有限文件／网表核对工具，不是通用 EDA 验证器或 ERC/DRC。`evidence/static-check.json` 保存本轮运行结果，路径做了可移植化替换；输入与输出 SHA-256 见该报告。

浏览器复现：打开 [嘉立创 EDA 标准版](https://lceda.cn/editor)，依次执行上表列出的文件入口；原理图保存后从 Protel/Altium 网表对话框保存文本，再与设计网络表逐项比较。仅在验证副本中做文字编辑，原 A0 文件保留不动。
