# 项目需求与执行计划

基线日期：2026-09-20。本文记录已提出的要求和后续执行约定；具体器件及尺寸以审核记录为准。

## 1. 产品目标与边界

产品是面向 Vibe Coding 的手持交互终端，游戏是附加用途。Mosaico 提供大脑、屏幕、语音与无线；底座提供实体输入、电池与握持结构。

第一阶段交付底座主板设计及其机械接口，第二阶段完成外壳和硬件打样验证，应用固件最后开发。最少必要的硬件测试程序或外部 I²C 测试工具用于验收，不提前扩展为应用软件项目。

优先目标依次为：接口正确、供电可靠、可装配、工厂可焊接、舒适且便于维修。外形尺寸、整机重量、续航和成本在完成器件与结构研究后量化，当前不虚构承诺值。

## 2. 需求与验收依据

| 编号 | 需求 | 验收方式 |
| --- | --- | --- |
| R01 | 完整 Mosaico 不改板、不焊线，能够拆装 | 样件装拆检查，核对所有原有部件完整 |
| R02 | 四触点实现 I²C 与供电，无 H1/H2 盲插和排线 | 对照官方原理图、坐标图和实物检查网络与触点 |
| R03 | 横向长条布局，左 D-pad、右 ABXY、顶部 L/R | 结构图和手持样件检查；Mode 在布局冻结时决定 |
| R04 | 底座无第二颗可编程 MCU，无独立烧录工序 | 原理图、BOM 和装配流程检查 |
| R05 | 所有实体键由 I²C IO 扩展器采集 | 单键、组合键与持续按压测试；不依赖第五根中断线 |
| R06 | 使用低矮 tact switch 与打印键帽 | 工厂贴装确认；按键行程、限位和十字帽斜向操作检查 |
| R07 | 目标 1000–2000 mAh 单节电池 | 确认具体电芯／电池包规格、空间、保护、温度检测与接口 |
| R08 | 底座 USB-C 可充电与供电 | 明确输入电源要求后测试充电、边用边充、低电量和负载变化 |
| R09 | 原生 USB-C 保持可访问 | 插头实体空间检查；与底座 USB-C 同时连接时验证电源行为 |
| R10 | 原生音频、无线、传感器与操作入口保留 | 开孔、声路、天线避让与功能对比检查 |
| R11 | Pogo 接触由结构定位和压紧保证 | 核对针头落点、工作行程、累计公差、硬限位和装拆重复性 |
| R12 | 尽量由嘉立创完成所有焊接 | 审核实际库存、封装、贴装／手焊工艺及报价，列明例外 |
| R13 | 外壳可拆卸并有浅握把 | 样件检查装配顺序、螺丝可达性、握持和维修空间 |
| R14 | 工程可复用、可审核、可追溯 | EDA 工程可打开编辑；BOM、坐标、制造文件与同一版本一致 |

嘉立创 PCBA 的目标是交付焊接完成的板子。电池、线束、键帽、螺丝和外壳整机装配是否由供应商承接，需要另行确认，不能把 PCB 贴装等同于整机交付。

## 3. 设计方案与待冻结决策

### 已确定的方向

- 完整 Mosaico 可拆式模块仓，顶部放入、上压框固定。
- 单块贯穿左右的底座主 PCB，四 Pogo 接口，I²C 扩展按键。
- 工厂贴装优先，打印外壳和键帽，暂不做定制硅胶件。
- 独立底座电池、USB-C 充电与供电管理，保留 Mosaico 原生接口。
- 国内嘉立创／嘉立创 EDA 为目标设计和生产流程。

### 必须经过研究再冻结

- 模块外形与完整坐标系；四触点间距、直径、位置、公差和朝向。
- 模块厚度、Pogo 工作高度与压缩量、上下壳间隙、安装柱和板厚。
- 主板轮廓、按键中心与间距、肩键结构、电池位置、握把厚度。
- 最终 IO 扩展器、I²C 接口电路、Pogo、开关、USB-C 和电池型号。
- 充电／输入电流、输出能力、待机功耗、开关逻辑与双 USB 供电行为。
- 电池电量显示是否配置独立计量芯片；现有草案中的计量电路不是已确认需求。
- 目标成本、首批数量、生产工艺例外与采购清单。

机械与 PCB 共用一份接口约束，避免两边各自修改尺寸。PCB 先于外壳详细建模完成，但外壳的空间需求必须从 M1 起参与。

## 4. 工作节点与交付物

### M0：建立共同基线

交付本仓库说明、需求表、状态清单与协作规则。GitHub 仓库为 `ChromeTokyo/MosaicoKeyboard`，仓库根目录对应本项目目录。初始版本保留实际文件状态，并明确 A0 草案的验证限制。

### M1：冻结模块接口与空间约束

整理官方资料；建立前视、后视、底座顶视的坐标和方向示意；给出引脚表、模块外形、禁布区、开孔区域、Pogo 与电池尺寸链。

交付：接口规范、关键尺寸表、布局约束图、来源与未确认项。若官方精确尺寸仍缺失，可继续电路研究，但不得宣布机械接口冻结或放行依赖该尺寸的生产。

### M2：完成原理图与 BOM

完成按键、电源、接口保护与测试点设计；核对每颗 IC 引脚、外围参数、所有电源状态和总线逻辑电平；按国内工厂可采购与装配情况选择器件。

交付：可编辑原理图、网络表、BOM、关键计算与审核记录、ERC 结果。供应商器件库的存在不等于封装正确或可生产，必须单独核对。

### M3：完成 PCB 与生产检查

在 M1 约束和 M2 审核通过后布线，处理升压电源布局、回流、散热、接口保护、天线避让、按键与 Pogo 定位。输出原理图与 PCB 一致性检查、DRC 和可制造性检查结果。

交付：可编辑 PCB、三维预览、Gerber、钻孔、BOM、贴片坐标、装配图和工厂待确认项。制造输出来自同一冻结工程版本。

### M4：完成外壳与装配验证

按已冻结接口与 PCB 设计槽位、导向、限位、压框、声学开孔、接口开孔、握把和按键结构。检查电池与线束空间、元件高度和螺丝路径。

交付：可编辑三维源文件、STEP、打印文件、装配顺序与紧固件清单。尽量先用尺寸样件验证结构，实物到位后补齐模块装配验收。

### M5：首版制造

完成工厂询价、贴装能力和替代料确认，准备生产版本。数量、总价和最终下单内容在实际报价明确后确定；当前未产生订单。

交付：冻结制造包、版本号、供应商确认记录、PCBA 与外壳样件。

### M6：硬件测试与修改

先完成供电和充电测试，再连接核心模块；检查电压、电流、温升、低电量、插拔及双 USB 场景。核对 I²C 地址、按键组合、休眠／关机状态、电量计（若保留）和装拆接触表现。

交付：测试条件、记录、问题列表与修订版本。通过实物测试后，硬件才可标记为可进入应用固件开发的稳定版本。

### M7：固件与电脑端

硬件稳定后再定义实体键动作、触摸 UI、语音、任务列表、Agent 状态、批准／拒绝和电脑通信。不在当前 PCB 设计阶段扩大软件范围。

## 6. 建议首批 GitHub Issues

1. 核实 ESP-Mosaico 四触点引脚、朝向和精确机械尺寸。
2. 审核 USB-C、充电、电源路径、升压、限流及反灌处理。
3. 审核 I²C 电平、上拉、掉电状态与 MAX17048／缓冲器兼容性。
4. 完成国内嘉立创 BOM 供应、封装及贴装能力核对。
5. 冻结按键、电池、Pogo 与模块仓空间约束。
6. 验证嘉立创 EDA 工程导入、可编辑性和原理图一致性。
7. 完成 PCB 布局布线与 DRC。
8. 完成外壳、键帽和装配样件。
9. 准备首版制造包与硬件测试计划。

每个 Issue 写明输入、输出、验收条件、依赖和负责人。完成表示验收条件已满足，不能只表示生成了一个文件。
