# 团队分工与放行规则

版本：2026-09-20，第二次分工修订。本文替代此前将机械 CAD 分配给 Cursor 的方案。

## 1. 谁主导

**Claude Fable 5.1 负责项目主控、产品视觉与交互设计；Chrome GPT-6 统一负责电路、PCB 和外壳结构；Hiro GPT-6 按批次独立复核硬件。** Cursor、Grok 不承担核心设计、强制审查或任何交付的唯一责任。

按用户最新取舍，宁愿等待也不为并行速度转移关键硬件职责。此分工体现用户偏好与资源安排，不宣称已有基准证明 GPT 能保证电路或外壳一次成功；放行依据仍为原厂资料、工程检查、独立复核与实物测试。

这是责任分配，不代表这些会话已经启动、获得仓库权限或能够跨平台自动互相调用。Claude 作为主控需要在其自己的运行环境中被启动；订阅额度大也不等于机器会持续在线。

用户已确认 Hiro、Chrome 均可用 GPT-6，Claude 可用 Fable 5.1。Hiro 会间歇上线完成工作后关机；Chrome 更适合持续工程任务；Claude 有较充足的可用额度。此信息是用户对当前资源的说明，不是对平台套餐和通用限额的声明。

选择模型时记录实际模型 ID 与推理档位。关键设计及审查使用已确认可用的旗舰模型和适合复杂任务的高推理档位；额度耗尽时提交交接并暂停，不静默降级，也不自动把电路、PCB、CAD 或验收任务转给 Cursor／Grok。辅助工具如需启用，只领取范围明确、输出可由负责人核验的任务。

Chrome 是电气和机械源文件的统一负责人，可使用分开的电气／机械任务会话，但共用冻结接口，同一源文件同时仅一位编辑者。允许分阶段串行执行，不为填满所有账号而拆散设计责任。Hiro 原则上通过审查报告提出修改；确需 Hiro 接手设计时先明确文件移交，并重新指定非作者审查人。

Claude 提出视觉语言、屏幕信息层级、按钮语义及外观概念；Chrome 将获采纳的方向落实为可制造结构。Claude 不能为了视觉效果自行更改触点、板框、孔位、壁厚、按键行程或电池空间。界面完整设计、原型与实现仍放在硬件稳定后；当前只明确影响实体按键和开孔的交互需求。目录尚不存在时由负责人创建，不把规划路径视为已有交付。

辅助资料不能直接进入冻结设计，不用模型投票决定工程正确性。普通联网查询不需要额外委派；联系供应商、发送项目文件、采购或付款须已有对应用户授权。本计划本身不授权对外发送消息。

## 3. 主控如何工作

Claude 每次开始时读取当前 `main`、`AGENTS.md`、本文件、`docs/TASK_BOARD.md` 和 `docs/DESIGN_STATUS.md`，再查看相关交接与 PR。任务状态以仓库记录为准，不能只保存在聊天记忆里。

主控负责维护一个有序任务队列，明确每项工作的输入提交号、依赖、负责人、文件范围、验收条件和复核人。普通工作不等待 Hiro 在线；关键节点若指定独立审查尚未完成，维持待审状态，其他不依赖它的工作继续。

主控离线时，其他角色继续已领取且输入稳定的任务；不自行修改冻结接口或扩大任务范围。Chrome 可整理状态和提出集成建议，但不得越过放行条件或批准自身电路／结构。Claude 管理项目集成，硬件技术结论由 Chrome 提交、Hiro 独立复核；材料完整不等于技术通过。

## 4. Hiro 的批次审查

Hiro 每次上线领取一个可独立完成的审查包，建议按以下顺序拆分，而不是一次审整台机器：

1. **H1 电源与接口：** 全供电状态、电流／热预算、反灌、逻辑电平、掉电与上拉。
2. **H2 原理图与 PCB：** 器件脚号、封装、关键布局、回流、保护、测试点及源文件一致性。
3. **H3 机械与装配：** 触点方向、Pogo 尺寸链和弹力、按键行程、电池与插头空间、安装与维修路径。
4. **H4 制造包与寄送资料：** 制造版本一致性、国内试装和实测证据、未解决项。

每个审查包包括冻结提交号、可编辑文件、必要导出图、原厂资料索引和问题范围。Hiro 先独立查证、计算，再对照作者结论。输出为 `PASS`、`CHANGES_REQUIRED` 或 `BLOCKED`；证据不全时不能使用 `PASS`。

Hiro 关机前提交并推送报告与交接，注明复核过的提交号。无法完成时写清已查范围和未查范围。不能让审查结果只留在本机，也不能承诺等待中的工具会在关机后继续执行。

原 A0 草案由当前 Hiro 会话产生，因此对原 A0 的第一次独立技术审查由 **Chrome GPT-6** 执行，Claude 可以补充跨模型质疑。Chrome 修订后的新设计交给 Hiro 复核；Hiro 披露参与过 A0，对保留的原 A0 电路仍保留 Chrome 的独立审查记录，不能把自审算成独立复核。

若 Hiro 暂不可用，普通工作和 Claude 的补充审查继续，规定的 GPT 独立硬件审查等待 Hiro；不得自动让 Cursor 代签；Grok 的第二道复核（2026-09-21 起常设）同样不替代规定的 Hiro 批次复核，两者并列。需要更换核心审查责任时，必须经用户明确调整。两位 GPT 的意见也可能同错，原厂证据、工具检查、专业工程师复核建议与国内实物验收仍须分别落实。

## 5. 工程交接约定

- 每个角色使用自己的 clone 或 worktree 和分支，不共享正在编辑的工作目录。
- **进展同步是强制项。** 领取任务、完成任一可独立检查的中间步骤、遇到阻塞、会话结束或额度耗尽时，各端都要把进展记录推送到 `docs/handoffs/<角色>.md` 的“进展日志”表，不能等到任务全部完成才第一次出现。进展记录是事实陈述，不是完成度声明；主控据此更新 `docs/STATUS.md`，并在某端长时间无记录时提示用户催办。
- 任务先领取再修改，领取记录写入任务板；并发领取产生冲突时由 Claude 决定，不能靠约定文字声称已实施自动锁。
- PR 记录所用模型、输入提交号、改动文件、工程依据、已做检查、未做检查与风险。
- 报告必须对应一个具体提交版本。修改关键网络、器件、板框、孔位或尺寸后，旧报告对受影响范围失效。
- 没有 Git／终端能力的会话先输出带来源的资料包，由 Claude 核对入库，不假称已经提交或修改远端。
- `docs/INTERFACE_CONTROL.md` 由 Chrome 维护，必须涵盖电气与机械约束；Hiro 复核关键接口，Claude 记录冻结版本和任务依赖。该文件尚待创建，不能视为接口已经冻结。
- 项目结构中每个原生 EDA／CAD 文件只保留一个权威设计源，脚本与导出文件的从属关系必须写明。

交接统一包含：任务 ID、角色与模型、输入提交、输出提交／PR、完成内容、证据路径、未解决问题、下一步、继续工作的条件。模板见 `docs/handoffs/TEMPLATE.md`。

## 6. 必须通过的质量节点

| 节点 | 放行证据 | 负责准备／复核 |
| --- | --- | --- |
| G0 工具与资料可用 | 真正 EDA／CAD 能打开、编辑、保存和导出；关键模块尺寸有官方图纸或实测，假设明确 | Chrome 准备证据；Claude 核对完整性 |
| G1 共同接口冻结 | 坐标系、触点、板框与孔、禁布和高度、电池空间、Pogo 公差及行程均有依据 | Chrome 提交；Hiro 专项复核；Claude 记录冻结版本 |
| G2 电气冻结 | 电源全部状态、关键参数计算、引脚／封装、总线电平、ERC、问题关闭记录 | Chrome 准备；Hiro 批次复核；Claude 补充跨模型审查 |
| G3 PCB 与结构冻结 | PCB 完整布线与检查，关键回路审查；参数化装配、公差、按键和实际工艺样件验证；相关阶段没有未解决的阻断项 | Chrome 准备；Hiro 复核 PCB 与结构；Claude 汇总；硬件／结构工程师复核建议待落实 |
| G4 国内制造与出厂检查 | 同版制造包、选定器件与工艺确认；工厂侧可执行的检查完成并留证（PCB 电测、AOI、贴装与目检、可选的上电与飞针项目） | Chrome 核对工程结果与工厂能力；Hiro 独立核查；Claude 汇总。本节点**不包含整机功能验收** |
| G5 寄送准备与发运 | 待寄实物与制造版本身份一致；备板与备件数量确定；可维修性与拆装说明完整；电池运输合规方案确定；装配照片与出厂记录齐全 | Claude 准备放行资料；Chrome 确认版本与备件覆盖；用户决定寄送 |
| G6 日本整机验收 | 按规程完成分步上电、电气、充电与双 USB、I²C、按键与触点、温升测试并记录；问题闭环或明确遗留 | Chrome 提出测试规程、条件与通过阈值；Hiro 独立复核规程；**用户在日本执行并记录**；Claude 汇总与放行 |

原理图 ERC／PCB DRC 不能替代电源设计验证；三维无干涉不能替代按键与握持样件验证；供应商贴装检查不能替代整机功能验收。测试计划应在制造前明确条件、仪器和通过阈值，不能测试后才降低标准。

**放行链变更（2026-09-20）：国内不设实物验收执行人。** 最后一道整机实测在日本由用户执行，因此任何需要通电才能发现的问题都将在跨国运输之后暴露，修复成本显著高于原方案。为补偿这一点，以下为强制设计与发运约束，缺一不可放行 G3：

- 硬件必须具备测试点、分步上电通路（可在不接电池、仅 USB 供电下验证电源级）、输入与输出限流保护、关键器件可更换（不使用难以返修的封装承担关键功能）、故障可观测手段（指示灯或可读取的状态输出）。
- 制造批量必须包含备板与关键备件（触点弹针、电池连接、键帽与结构件），一次寄足，避免为单个损件重新国际运输。
- 测试规程、判据与故障树必须在发运前写成用户可独立执行的步骤，由 Hiro 复核可执行性，不能假设日本端具备工程调试能力。
- 结构样件可在日本本地增材制造迭代，不必等待国内批次；但最终工艺样件仍须与制造版本对应。
- 锂电池国际运输受限，电池选型应优先考虑用户所在地可合法采购的规格；运输方案未确认前不得把电池默认计入寄送清单。

制作研究用结构样件可以早于正式冻结，但要标记用途与假设，不能拿研究样件的通过状态代替最终工艺和版本的验证。

## 7. 排期原则

**2026-09-20 晚，用户确定项目主循环（D-017）：** ① 基于现有信息先把主板与外壳设计做完（全部标 ASSUMPTION）→ ② 实物到货后按测量手册核尺寸、读 eFuse 版本 → ③ 修改设计，逐条关闭 ASSUMPTIONS.md → ④ 国内打板、发日本 → ⑤ 日本验证（G6），修改，再打。**接受迭代打板**：每轮打板前仍须非作者复核与 G3 的远程验收补偿约束，但不再要求 G1／G2 完全冻结后才能打第一版。原「冻结后再打板以减少跨国返工」的原则由用户权衡后放宽；返工运输成本由用户承担。

按质量节点推进，不把早期 6–8 周估算作为完成期限。Chrome 同时承担电气与机械，允许分阶段串行完成；Hiro 审查窗口和实物验证纳入计划，等待额度恢复也不降低设计或审查要求。

推进顺序：工具链与原始资料 → 共同接口和空间约束 → 电路与结构研究 → PCB 与详细 CAD → 独立复核与实际工艺样件 → 国内整机测试 → 修订复验 → 寄送。产品视觉提案可在不改变硬件约束时并行，应用 UI 和固件开发仍在硬件稳定后。

用户已购入 ESP-Mosaico 实物，预计 2026-09 下旬送达日本用户本人手中，模块精确机械测量因此可以由用户执行，测量规程由 Chrome 提出。国内实物验收执行人确定不设立，整机验收改由用户在日本完成，对应质量节点 G6。测量与验收所需器材由用户采购，清单由 Chrome 在规程中确认。

实物到手不等于 O01 解除：必须按规程完成测量、留下可核对的照片与数据、并由 Hiro 复核由测量导出的接口约束，才能进入 G1。应用固件最后处理；用于硬件验收的最小测试程序应在发运前完成，属于 G6 的前置条件。
