# 团队分工与放行规则

版本：2026-09-20。本文替代此前的通用 Agent 分工建议。

## 1. 谁主导

**Claude Fable 5.1 是项目主控与总集成负责人；Chrome GPT-6 是电路和 PCB 负责人；Hiro GPT-6 是按批次工作的独立审查员。** Cursor 负责机械 CAD 与验证工具，Grok Bot 负责资料和供应链证据核查。

这是责任分配，不代表这些会话已经启动、获得仓库权限或能够跨平台自动互相调用。Claude 作为主控需要在其自己的运行环境中被启动；订阅额度大也不等于机器会持续在线。

用户已确认 Hiro、Chrome 均可用 GPT-6，Claude 可用 Fable 5.1。Hiro 会间歇上线完成工作后关机；Chrome 更适合持续工程任务；Claude 有较充足的可用额度。此信息是用户对当前资源的说明，不是对平台套餐和通用限额的声明。

选择模型时记录实际模型 ID 与推理档位。关键设计及审查使用已确认可用的旗舰模型和适合复杂任务的高推理档位；额度耗尽时提交交接并暂停，不静默降级。Cursor、Grok 的实际模型及工具权限由对应会话在接手时确认，不按产品名猜测。

Claude 主导结构方案和需求取舍，Cursor 是机械源文件的唯一编辑负责人。Chrome 负责 PCB 源文件；Claude 和 Hiro 通过审查报告提出修改，由负责人实施。文件目录尚不存在时，由领取任务的负责人创建，不把目录名视为已有交付。

Grok 的资料核查为其他角色提供输入，不用模型投票决定工程正确性。普通联网查询不需要额外委派；联系供应商、发送项目文件、采购或付款须已有对应用户授权。本计划本身不授权对外发送消息。

## 3. 主控如何工作

Claude 每次开始时读取当前 `main`、`AGENTS.md`、本文件、`docs/TASK_BOARD.md` 和 `docs/DESIGN_STATUS.md`，再查看相关交接与 PR。任务状态以仓库记录为准，不能只保存在聊天记忆里。

主控负责维护一个有序任务队列，明确每项工作的输入提交号、依赖、负责人、文件范围、验收条件和复核人。普通工作不等待 Hiro 在线；关键节点若指定独立审查尚未完成，维持待审状态，其他不依赖它的工作继续。

主控离线时，其他角色继续已领取且输入稳定的任务；不自行修改共同接口或扩大任务范围。Chrome 可整理状态和提出集成建议，但不得未经交接改换主控、越过放行条件或批准自身电路。

## 4. Hiro 的批次审查

Hiro 每次上线领取一个可独立完成的审查包，建议按以下顺序拆分，而不是一次审整台机器：

1. **H1 电源与接口：** 全供电状态、电流／热预算、反灌、逻辑电平、掉电与上拉。
2. **H2 原理图与 PCB：** 器件脚号、封装、关键布局、回流、保护、测试点及源文件一致性。
3. **H3 机械与装配：** 触点方向、Pogo 尺寸链和弹力、按键行程、电池与插头空间、安装与维修路径。
4. **H4 制造包与寄送资料：** 制造版本一致性、国内试装和实测证据、未解决项。

每个审查包包括冻结提交号、可编辑文件、必要导出图、原厂资料索引和问题范围。Hiro 先独立查证、计算，再对照作者结论。输出为 `PASS`、`CHANGES_REQUIRED` 或 `BLOCKED`；证据不全时不能使用 `PASS`。

Hiro 关机前提交并推送报告与交接，注明复核过的提交号。无法完成时写清已查范围和未查范围。不能让审查结果只留在本机，也不能承诺等待中的工具会在关机后继续执行。

原 A0 草案由当前 Hiro 会话产生，因此对原 A0 的第一次独立电气复核由 **Claude** 执行。Hiro 对后续由 Chrome 完成的新版本可以审查，但须披露参与过 A0，并由 Claude 保留跨模型复核，不能将回看自己原稿描述为完全独立审查。

若 Hiro 暂不可用，Claude 可以将普通审查分配给具备工具和资料访问能力的非作者；制造前已规定的独立复核必须实际完成。作者不能成为自己的替补审查员；找不到合适人选就等待，不能为了排期免审。

## 5. 工程交接约定

- 每个角色使用自己的 clone 或 worktree 和分支，不共享正在编辑的工作目录。
- 任务先领取再修改，领取记录写入任务板；并发领取产生冲突时由 Claude 决定，不能靠约定文字声称已实施自动锁。
- PR 记录所用模型、输入提交号、改动文件、工程依据、已做检查、未做检查与风险。
- 报告必须对应一个具体提交版本。修改关键网络、器件、板框、孔位或尺寸后，旧报告对受影响范围失效。
- 没有 Git／终端能力的会话先输出带来源的资料包，由 Claude 核对入库，不假称已经提交或修改远端。
- `docs/INTERFACE_CONTROL.md` 由 Claude 维护；Chrome 与 Cursor 对涉及自己的接口共同确认。该文件尚待创建，不能视为接口已经冻结。
- 项目结构中每个原生 EDA／CAD 文件只保留一个权威设计源，脚本与导出文件的从属关系必须写明。

交接统一包含：任务 ID、角色与模型、输入提交、输出提交／PR、完成内容、证据路径、未解决问题、下一步、继续工作的条件。模板见 `docs/handoffs/TEMPLATE.md`。

## 6. 必须通过的质量节点

| 节点 | 放行证据 | 负责准备／复核 |
| --- | --- | --- |
| G0 工具与资料可用 | 真正 EDA／CAD 能打开、编辑、保存和导出；关键模块尺寸有官方图纸或实测，假设明确 | Chrome、Cursor 准备；Claude 核查 |
| G1 共同接口冻结 | 坐标系、触点、板框与孔、禁布和高度、电池空间、Pogo 公差及行程均有依据 | Claude 汇总；Chrome、Cursor 共同确认；Hiro 可专项复核 |
| G2 电气冻结 | 电源全部状态、关键参数计算、引脚／封装、总线电平、ERC、问题关闭记录 | Chrome 准备；Claude 独立审查；Hiro 批次复核 |
| G3 PCB 与结构冻结 | PCB 完整布线与检查，关键回路审查；参数化装配、公差、按键和实际工艺样件验证；相关阶段没有未解决的阻断项 | Chrome、Cursor 准备；Claude 与非作者独立复核；硬件／结构工程师复核建议待落实 |
| G4 国内制造与整机验收 | 同版制造包、选定器件与工艺确认；国内真实 Mosaico、PCB、电池、外壳试装；电气／按键／接触／温升测试及记录 | 国内执行人待落实；Claude 汇总；Hiro／非作者核查 |
| G5 寄日本 | 待寄实物与已测试样机身份、版本一致；问题关闭、装配照片、测试记录、备件和运输安排完整 | Claude 准备放行资料，国内执行人确认实物，用户决定寄送 |

原理图 ERC／PCB DRC 不能替代电源设计验证；三维无干涉不能替代按键与握持样件验证；供应商贴装检查不能替代整机功能验收。测试计划应在制造前明确条件、仪器和通过阈值，不能测试后才降低标准。

制作研究用结构样件可以早于正式冻结，但要标记用途与假设，不能拿研究样件的通过状态代替最终工艺和版本的验证。

## 7. 排期原则

以 6–8 周硬件开发与国内验证作为初步规划，国际运输另计；资料、器件和实测结果可能改变时长。这不是交期承诺，也不以赶进度为理由减少检查。

- 第 1 周：工具链、官方资料／实物测量、国内验证条件与接口初稿。
- 第 2 周：电路设计、独立计算、器件与电池选型，机械空间布局并行。
- 第 3–4 周：PCB、参数化外壳、交叉复核、结构样件与制造准备。
- 第 5–6 周：国内 PCBA 与结构样件、整机装配与实测。
- 第 7–8 周：必要修订、复验、备件和寄送资料；未通过则延长。

用户当前没有 Mosaico 实物；国内持有实物并执行验收的人／服务商也尚未落实。这两项是降低国际返工的关键依赖。应用固件最后处理；用于硬件验收的最小测试程序可以提前制作。
