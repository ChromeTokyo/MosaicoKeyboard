### D-005 队列字段扩展

领取记录的四个字段用于让任何角色从仓库单独判断一项工作的可接续性：输入提交号确定该工作基于哪一版仓库，分支确定改动在哪里，文件范围确定与其他角色的冲突边界，交接路径确定去哪里读上下文。

### D-006 design/ 生成产物的使用限制

本轮在仓库外的临时副本中重跑了 `design/build_design.py`，脚本退出码 0，仅依赖标准库。这只说明代码可以执行并写出文件，不说明电路正确、封装正确或可生产；输出文件自身也标注 `DRAFT`、`NOT FOR FABRICATION`、`GEOMETRY TBD`。

按第 5 节「依据必须指向可核查的对象」的要求，这次重跑的复现步骤与结果如下，被指派解除本节未知项的角色可独立重跑核对，不必依赖本会话的描述：

```
TMP=<任意仓库外空目录>
cd <本仓库 clone>
git archive 099af5b | tar -x -C "$TMP"
cd "$TMP" && /usr/bin/python3 design/build_design.py   # 退出码 0
cd <本仓库 clone>
for f in design/mosaico-dock-schematic.json design/mosaico-dock-placement.json \
         design/design-netlist.json design/bom-review.csv design/pin-net-review.csv; do
  diff --strip-trailing-cr <(git show 099af5b:$f) "$TMP/$f"
done
```

本轮执行环境为 `/usr/bin/python3`（3.9.6），重跑在仓库外的临时目录进行，仓库文件未被改动。差异行数（`diff` 输出中以 `<` 或 `>` 开头的行，已忽略行尾差异）：

| 文件 | 差异行数 |
| --- | --- |
| `design/mosaico-dock-schematic.json` | 24 |
| `design/mosaico-dock-placement.json` | 24 |
| `design/design-netlist.json` | 30 |
| `design/bom-review.csv` | 24（对应 12 个数据行） |

关键发现是：`design/` 与 `references/` 在同一提交 `099af5b` 入库，但用该提交自带的 `references/` 重跑，得到的四个生成文件与仓库已提交版本不一致。这说明仓库中已提交的生成产物对应一个更早、缺少部分库缓存的输入快照，脚本、输入与输出三者当前不自洽。
